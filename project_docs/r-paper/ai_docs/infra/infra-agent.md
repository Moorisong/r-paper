# Infra Agent Reference

## 📝 1. 연동 기획 명세 (`deployment_spec.md`)
본 서비스(Haroo Paper)는 Ubuntu Server 인프라 환경에서 운영되며, 무중단 서비스를 제공하기 위한 배포 스크립트를 포함하고 있습니다.
* 배포 대상 인프라는 Nginx(리버스 프록시)와 PM2(Node.js 프로세스 관리)를 활용합니다.
* 셸 스크립트를 통해 원클릭으로 백엔드(Git Pull & PM2 Restart) 및 프론트엔드(정적 빌드 파일 압축 전송 & Nginx Reload)를 배포합니다.
* 프론트엔드의 경우 자동 백업과 긴급 롤백(Rollback) 기능을 통해 장애 시 즉각 구버전으로 복원할 수 있는 시스템을 갖추고 있습니다.

## 🤖 2. AI 개발 지침 및 설계 구조
### 🎯 목적
서버의 보안과 안정성을 유지하며, 빠르고 안전한 무중단 배포 및 설정 환경 구축을 지향합니다.

### 📦 타깃 경로 구조
* `/home/ksh/r-paper/backend`: 서버 내 백엔드 코드 소스
* `/home/ksh/srv/r-paper-web/dist`: 서버 내 프론트엔드 호스팅 루트 디렉토리
* `/etc/nginx/sites-available/r-paper-web.haroo.site`: Nginx 설정 파일

### 🛠️ 개발 단계 (Step-by-Step 상세 로직)
1. **Nginx 라우팅 구성**: 리버스 프록시 연결 및 `index.html` 폴백 라우팅 처리 등 Nginx 설정.
2. **배포 스크립트 작성**: SSH 접속 및 원격 명령어 실행 제어(예: `.sh` 스크립트) 환경을 제공.
3. **PM2 클러스터 관리**: 에러 및 로그 모니터링 적용 및 클러스터 모드 재시작.
4. **권한 관리**: `www-data` 사용자가 소유하는 권한 구조(chown, chmod) 및 디렉토리 관리.

## 🚨 3. 철벽 코드 컨벤션 및 제약 조건
- **[300줄 분리 규칙]:** 단일 스크립트/설정 파일이 300줄을 절대 초과할 수 없으며, 과도하게 복잡한 배포 로직은 개별 함수/파일로 모듈화하십시오.
- **[운영 환경 접근 락]:** 인프라 환경 파괴 위험을 고려하여 실제 프로덕션 DB 및 기존 라이브 서버 프로세스를 강제로 `kill`하는 명령은 피하고, graceful reload를 수행합니다.
- **[하드코딩 금지]:** 접속 IP 주소, 포트 번호, 그리고 계정 정보 등은 스크립트 내부 인자로 받거나 외부 변수로 관리하여 유연성을 확보합니다.
